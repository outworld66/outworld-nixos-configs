# Stoat on Rico

Stoat is hosted at `https://stoat.outworld66.ru`. The NixOS configuration runs its API, event gateway, upload service, metadata proxy, and web client as a Docker Compose stack managed by systemd. MongoDB and uploaded files persist under `/var/lib/stoat` and `/srv/stoat/files`; the latter uses the merged `/srv` mount.

The forked API enables Pocket ID OpenID Connect. The callback is `https://stoat.outworld66.ru/api/auth/session/oidc/callback`. Stoat is served directly by Caddy without Pomerium. Pocket ID allows the `stoat` client only for members of the `stoat-admin` and `stoat-user` groups. Private Nix configuration provisions the mapped users and those groups. After Pocket ID verifies the email claim, the API creates a Stoat account on first login and the user chooses a Stoat username. An existing pending Stoat account is verified by that same OIDC claim. Password login and password registration are disabled in the API and web client while OIDC is configured. Pocket ID groups do not grant Stoat privileges; new Stoat accounts receive the normal default permissions.

The first deployment generates persistent RabbitMQ, S3, file-encryption, and VAPID secrets in `/var/lib/stoat/secrets.env`. Pocket ID provisions the `stoat` OIDC client; its runtime secret is written to `/var/lib/stoat/oidc.env`. These runtime files are root-owned and are not stored in Git or the Nix store. Back up `/var/lib/stoat` and `/srv/stoat/files` together.

Voice and video use Stoat's LiveKit server and voice-ingress containers. Rico's firewall opens TCP `7881` and UDP `50000-50100`; forward these ports on the router to `192.168.0.4` for calls from outside the LAN. To verify the service, check `systemctl status stoat`, `docker ps --filter label=com.docker.compose.project=stoat`, and `curl -H 'Host: stoat.outworld66.ru' http://127.0.0.1:15000/.well-known/stoat`. Unauthenticated visitors reach Stoat directly; OIDC login is limited by the Pocket ID client group allowlist. Recover with `systemctl restart stoat`; roll back the system generation with the documented server rollback procedure.
